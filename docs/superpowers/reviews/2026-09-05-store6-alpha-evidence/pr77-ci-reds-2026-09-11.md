**Mechanism.** Commit `1b4620e6` (Task 7, review item K-10) replaced the test's original
`requests in 2..3` tolerance — whose message already said "the 304 cycle may self-heal one obsolete
cold-baseline launch" — with an exact `requests == 2` and an exact single-entry revalidation
list. The exact form held on JVM, macosArm64, jsNode, and wasmJs (30 local runs each) but not on
linuxX64, iosSimulatorArm64, or the Android unit lane, where the cold-path engine issues the
documented extra launch. The ktor kit's own changes on this branch (204/205 refusal, the
mapper-NotModified rule, the foreign-validator guard) do not produce extra requests; a refused

**Classification.** Test-side over-tightening of a known, documented, core-owned
nondeterminism (the same one the module's sample tolerates on the Last-Modified path). Not a
kit regression, not infrastructure.

**Disposition.** Restore the documented tolerance in the integration test while keeping the
assertions that carry the guarantee (the cold read is unconditional; every later request carries
the stored validator; exactly one `Revalidated` emission; staleness cleared), with a message
that prints the observed request sequence. The engine-side nondeterminism stays a follow-up for
the core owner (recorded in the plan ledger); the exact count is not a promise this module makes.
