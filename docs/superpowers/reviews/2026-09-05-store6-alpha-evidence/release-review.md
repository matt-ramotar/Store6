## R1 — P1: publishing does not depend on the complete release matrix

`.github/workflows/ci.yml:93-100,140-159` gives `publish` only `needs: build-and-test`. `.github/workflows/store6.yml:3-9` starts an independent workflow on the same tag. Therefore a valid upstream release tag can upload and release Maven artifacts while Apple tests, Swift dumps, KLIB inspection, or native stress fail or remain running. The tag/version and repository guards are real counter-evidence against accidental arbitrary-version release, but do not establish the missing dependency. `RELEASING.md:64-66` says the tag also runs the full matrix, without a wait. Source-proven missing release dependency; no bad publication attempted or observed. Fix: make the full validation reusable and depend on it, or verify all required workflows' success at the exact tag SHA before granting publication. Regression: fake or isolated workflow test with each required lane failed, absent, cancelled, wrong-SHA, and pending must refuse publication; only complete same-SHA success proceeds. Include scheduled full-suite execution provenance and explicit accepted classifications. Never use a newer head's green status to authorize this tag.

`.github/workflows/store6-full-jvm.yml:34-44` allows Gradle caching and counts XML files as executed suites. Latest live run `33956908960`, 2026-09-05, exact review SHA, is success. `ci.yml:140-159` ends with Maven publication; no GitHub Release creation/verification exists in the workflow inventory. `RELEASING.md:32,68-73` merely says update CHANGELOG and state the next month; no GitHub release receipt step. `STABILITY.md:105-107` requires a community issue linked to its conformance guarantee. `CHANGELOG.md:5-57` has no such closure, says all ten modules are experimental-track (core is stable-track per STABILITY:47), and contains a prewritten 2026-08-21 date and September next-alpha target. Source-proven missing linkage and tier contradiction; draft dates/status are preparation items, not evidence that publication already occurred. Add a release-note template/check and idempotent GitHub Release creation after successful publication, or verified publication receipt and explicit release owner task; record failed release-note creation as partial release, never republish Maven blindly. Select community issue from actual evidence, do not invent closure authority.

## R6 — P2, outside alpha allowlist: file names collapse malformed UTF-16 keys

`file/.../internal/Base32.kt:17-19` calls `encodeToByteArray()` with its replacement behavior. Distinct unpaired surrogate strings (e.g. U+D800 and U+D801) become the same encoded filename, while Store key identity remains distinct. `FileNames` validates byte length, not malformed input. A later write can replace the other key's file. Source-based candidate requiring Kotlin regression execution; do not claim Python emulation as Kotlin evidence. Reject invalid sequences before any disk mutation and before Bookkeeper state changes, with Unicode collision and valid Unicode round-trip tests. The file module is not currently published by alpha allowlist, so this does not expand alpha floor.
